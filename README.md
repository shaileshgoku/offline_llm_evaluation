# Offline LLM Evaluation Framework Using LLM-as-a-Judge

An end-to-end application that evaluates Large Language Model (LLM) responses using another AI model as a judge.

The project demonstrates how to systematically evaluate LLM-generated responses using predefined evaluation criteria, reference answers, and contextual information.

## Overview

Generating an answer is only one part of building an AI application.

How do we know whether that answer is accurate, relevant, complete, concise, and supported by the available information?

This project explores **LLM-as-a-Judge**, an approach where one language model evaluates the responses generated by another language model.

The framework uses:

- Google FLAN-T5 Small as the candidate model.
- Laya as the evaluation judge.
- A synthetic e-commerce knowledge base.
- A golden evaluation dataset.
- Five evaluation dimensions.
- Streamlit for the user interface.

## Project Components

### 1. Knowledge Base

A synthetic e-commerce customer support knowledge base containing 100 policies across 10 categories.

Categories include:

- Returns
- Delivery
- Cancellation
- Refunds
- Payments
- Exchanges
- Order Tracking
- Order Modifications
- Warranty
- Customer Support

The knowledge base provides contextual information for answering user questions.

### 2. Golden Evaluation Dataset

A benchmark dataset containing 100 test cases.

Each test case includes:

| Field | Description |
|---|---|
| Test ID | Unique test case identifier |
| Policy ID | Reference policy identifier |
| Category | Question category |
| Difficulty | Test difficulty |
| Question | Input given to the model |
| Context | Relevant information provided to the model |
| Golden Answer | Reference answer |
| Evaluation Criteria | Conditions used to judge the response |

Difficulty distribution:

- Easy: 40 test cases
- Medium: 30 test cases
- Challenging: 30 test cases

### 3. Candidate Model

**Google FLAN-T5 Small**

The candidate model generates responses based on the user's question and retrieved context.

The model is instructed to answer using only the information provided in the context.

### 4. AI Judge

**Laya**

Laya evaluates the candidate model's response against the evaluation criteria.

It provides structured judgments using three possible outcomes:

- Pass
- Partial
- Fail

The judge evaluates each response across five dimensions.

## Evaluation Dimensions

### 1. Correctness

Is the information provided in the response factually accurate?

### 2. Relevance

Does the response actually answer the user's question?

### 3. Completeness

Does the response include all the essential information?

### 4. Conciseness

Is the response clear and to the point without unnecessary information?

### 5. Faithfulness

Are the claims in the response supported by the provided context?

A simple way to understand faithfulness is:

**Faithfulness Score = Supported Claims / Total Claims × 100**

Example:

- Total claims: 2
- Supported claims: 1
- Unsupported claims: 1

Faithfulness Score = 1 / 2 × 100 = **50%**

An unsupported claim may represent a hallucination because it is not grounded in the supplied context.

## Offline Evaluation vs Online Evaluation

These are two complementary approaches.

| Offline Evaluation | Online Evaluation |
|---|---|
| Uses predefined datasets | Uses real-world application interactions |
| Conducted before or outside live user evaluation | Conducted during live operation |
| Uses a controlled test environment | Uses a real user environment |
| Supports repeatable comparisons | Captures actual user behaviour |
| Identifies potential model weaknesses | Identifies issues emerging in production |

This project focuses on offline evaluation using a predefined benchmark dataset.

The Streamlit application provides three main sections:

**1. Live Evaluation**
- Enter a customer support question.
- Retrieve relevant policy context.
- Generate a response using FLAN-T5 Small.
- Evaluate the response using Laya.
- View Pass, Partial, and Fail judgments.
- Inspect evaluation probabilities.

**2. Benchmark Results**
- Explore the predefined evaluation dataset.
- Review evaluation distributions.
- Inspect individual evaluation results.
- Download evaluation results as CSV files.

**3. About**
- Understand the framework.
- Explore the evaluation methodology.
- Review project limitations.

## Installation and Local Execution

Clone the repository:

```bash
git clone YOUR_GITHUB_REPOSITORY_URL
```

Navigate to the project directory:

```bash
cd offline_llm_evaluation
```

Install dependencies:

```bash
pip install -r requirements.txt
```


The application is deployed using **Streamlit Community Cloud**.

Deployment steps:

1. Push the project files to GitHub.
2. Open [Streamlit Community Cloud](https://share.streamlit.io/).
3. Connect your GitHub repository.
4. Select `app.py` as the main file.
5. Deploy the application.

No paid LLM API is required by this implementation.

Model downloads and inference happen within the application environment. Deployment availability depends on the available memory, CPU, and hosting limits.

## Limitations

This project is an educational implementation designed to understand the LLM-as-a-Judge concept.

Important limitations:

- The evaluation dataset contains only 100 synthetic test cases.
- The dataset has not undergone extensive cleaning.
- Neither the candidate model nor the judge model has been fine-tuned.
- Golden answers are derived from the synthetic policy contexts and have not been independently human-verified.
- Evaluation criteria are not independently validated.
- Laya's confidence values may be uncalibrated.
- Automated judgments should not be treated as definitive human evaluations.
- The application is not production-ready.

The results should therefore be interpreted as an exploration of the evaluation process, not as a comprehensive assessment of model quality.
